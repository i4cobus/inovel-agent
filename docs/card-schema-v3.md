# 书卡词表 v3（2026-10-10，代码 `src/retrieval/card_schema.py`，prompt `card_v3`）

v2 的二级题材是从起点书库抄的，起点的二级是给作者投稿用的：很多项互相重叠，很多项其实是元素而不是题材。
两个 API 模型（Qwen3.8-Flash、Qwen3.7-Plus）各跑 120 本试点后（`docs/book-cards-pilot.md`），按一条规则重建：

> **一个二级必须只属于一个一级（一级由二级推导），且能用一句话和同级区分开。** 本质是元素的（系统、穿越、
> 直播、同人、争霸）不做二级；否定或唯一性断言（无感情线、单女主）不做元素，一句摘录证明不了"没有"；
> 书写的是谁（单一男主 / 单一女主 / 群像）是一个单选的风格维度，不是元素。

## 风格：五维（v3.2，2026-10-10）

| 维度 | 档位 |
|---|---|
| 主角结构 | 单一男主 / 单一女主 / 群像 |
| 爽度 | 高 / 中 / 低 |
| 基调 | 轻松搞笑 / 热血 / 沉重压抑 / 温馨日常 / 悬疑惊悚 |
| 感情线 | 无 / 单女主辅线 / 单女主主线 / 多女主 |
| 主角起点 | 开局无敌 / 普通 / 废柴逆袭 |

节奏在 v2.4 去掉（两模型在 55/119 本上相反）。**后宫在 v3.2 从元素层并入"感情线"**：它是整本书的综合判断，不是一句话能证明的桥段，
v3 试点里 Flash 在 10/116 本上抄词表定义当摘录、元素被丢（《我在日本的幸福生活》六个女生散在六章里）；v3.1 试过"写两个名字、程序核名字"，
用户指出判断该归模型，于是和感情线比重合成一维。"不要后宫"= 感情线≠多女主，"要单女主"= 感情线∈{单女主辅线, 单女主主线}，"要女主文"= 主角结构=单一女主。
模型把后宫当元素写时，解析转成 感情线=多女主（`ELEMENT_TO_STYLE`）。

## prompt（card_v3）相对 v2.4 的改动

1. 档案放在前面，词表和规则放在后面，规则离输出近。
2. 拿不准宁可不写：元素少列、二级留空，空比错好。
3. 只看主角本人和主角所在的世界；书中书、副本、被扮演的作品、梦境、配角身上的描写不算。
   起因：《变身路人女主》里 Flash 用配角的"连感情史都一片空白"判了无感情线。
4. 二级要和一句话、背景一致；穿梭多部已知作品的归诸天无限。
5. 摘录要直接体现元素定义里的特征（系统要看到面板、任务、奖励之类）。程序侧对 系统、修仙、穿越、重生 四个元素
   加特征词门槛（`ELEMENT_QUOTE_SIGNATURES`），摘录里一个特征词都没有就记 `element_weak_quote` 不算。
   起因：v2.4 里 34 条"系统"的摘录有 18 条是次元之门、主神、创世之阵。

## 什么叫稳

两条判据，满足就冻结、跑全量，之后词表只加不改：

1. 120 本试点里模型写出词表外二级的 ≤ 2 本、二级为空的 ≤ 5 本。
2. 人工抽审 30 本，没有同一类书系统性标错；单本错由一致性复核兜。
