## 二、三层结构

原则：每一层回答一种问题，用一种方式验证。

| 层 | 回答的问题 | 形式 | 验证方式 |
|---|---|---|---|
| 题材 | 这是哪一类书 | 二级单选（封闭），一级由映射推导 | 读简介即可判，人工审阅 |
| 元素 | 书里有没有某个设定 / 桥段 | 多选，封闭 | "有没有"，digest 能答，人工能核 |
| 风格 | 读起来是什么感觉 | 少数几个维度，每个三到四档 | 主观，看档位偏差而不是对错 |

另有两个自由字段：一句话简介（≤ 60 字）、关键词（≤ 5 个，只写类型词）。主角、背景、基调
三个短句字段保留，审阅里质量好。

### 第三层：风格（每项单选）

| 维度 | 档位 | 判断依据 |
|---|---|---|
| 爽度 | 高 / 中 / 低 | 高：冲突迅速解决、主角连续占上风、反复打脸；低：长期受挫、代价沉重 |
| 基调 | 轻松搞笑 / 热血 / 沉重压抑 / 温馨日常 / 悬疑惊悚 | 取最主要的一种 |
| 感情线比重 | 无 / 辅线 / 主线 | 主线：情节围绕两人关系推进 |
| 主角起点 | 开局无敌 / 普通 / 废柴逆袭 | 开篇主角实力相对周围人的位置 |
| 节奏 | 快 / 中等 / 慢热 | 保留 v1 |

### 自由字段

- 一句话简介 ≤ 60 字，不剧透结局。
- 关键词 ≤ 5 个，**只写类型词，不写人名、虚构地名、机构名、书名**；唯一例外是同人文写原作名。
  用来兜词表没覆盖的东西（如"反套路""摸鱼"）。

## 四、怎么用

- 检索：题材二级（及推导的一级）、元素、风格全部写进卡片文本进多向量索引第 12 段；候选预览换成一句话 +
  元素标签。
- 约束：用户的"要 X / 不要 X"先映射到元素或风格档位（不要系统 → 元素无"系统"；不要后宫 →
  元素无"后宫"；不要爽文 → 爽度≠高）；映射不到的词（圣母、小白、狗血、文笔差）走
  `check_trope` 读正文或直接告诉用户不确定。
- 验证：人工审阅页面按三层分别计：题材对 / 错，元素每条对 / 错 / 漏，风格档位偏差 0 / 1 / 2 档。

## 六、实现备注

- 词表在 `src/retrieval/card_schema.py`，prompt 和解析在 `src/retrieval/cards.py`（`card_v2`）。

- 词表外的词不丢进字段，记在卡的 `dropped` 里；`32_build_book_cards.py --report` 汇总每个标签的
  使用次数和词表外的词，用来看词表漂移和缺口。
- 人工审阅页面（脚本 37）按三层计：题材二级对 / 错，元素每条 ✓ / ✗ 加漏掉的，风格每维 对 / 偏一档 / 差很多。
